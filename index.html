Network Architecture & Systems

Networking & Stripe Backend

1. TCP/IP Protocol Stack Breakdown

Step-by-step transmission flow when a student completes an order:

Layer 4: Application

HTTP/HTTPS & JSON

Browser executes Stripe.js to generate a secure token, packages the order as JSON, and sends an HTTPS POST request to /api/charge.

Layer 3: Transport

TCP Handshake

TCP executes a 3-way handshake (SYN, SYN-ACK, ACK) and splits data into sequence-numbered segments to prevent packet loss.

Layer 2: Internet

IP Addressing & Routing

IP envelopes TCP segments with source and destination IP headers, routing datagrams across local gateways and network hops.

Layer 1: Network Access

Ethernet / 802.11

NIC translates binary packets into physical frame signals (Wi-Fi radio waves or Cat6 electrical voltage) to reach the switch.

2. Transmission Media

Wireless Media (Wi-Fi 802.11 / Cellular)

PEEL: Wireless transmission uses radio frequency (RF) waves through the air without physical cables. When a student places an order on their phone, data is modulated across the 2.4/5 GHz band to a campus WAP. For example, a student in the BHHS library transmits across the school WPA2 network to a ceiling router, offering high mobility and accessibility for canteen pre-ordering.

Wired Media (Cat6 Copper & Fibre Optic)

PEEL: Wired transmission media guides physical electrical or light signals down cables. Inside the school, the canteen POS terminal transmits orders over Cat6 twisted-pair copper cables to a switch, then over single-mode fibre optic lines between school buildings. For example, kitchen orders print reliably via Ethernet, providing superior bandwidth, low latency, and immunity to interference during busy lunch breaks.

3. Network & Payment Security

Encryption (HTTPS & Tokenization)

All data in transit is protected via TLS 1.3 / HTTPS encryption. Credit card data is collected via sandboxed Stripe iframes, tokenizing credentials directly to Stripe's PCI-DSS Level 1 servers. The canteen server never stores or views raw card numbers.

User Authentication & Validation

Student input data is validated with client-side checks and regex patterns. Server communications are authorized using protected backend secret keys (sk_test_...) stored strictly server-side.

Compliance, Ethics & Policies

Terms & Conditions

Privacy & Digital Footprint

  • What is collected: Student name, contact number, pickup time slot, food choices, and allergy notes. No credit card details are ever stored.
  • Why it is collected: To verify student orders at the counter and ensure correct meal packaging for recess or lunch.
  • Data retention: Personal order records are retained only for the school day of fulfilment and wiped after 30 days.
